# CodeCraft Harness — 执行计划 v2.1（评审修正版）

> v2.1 相对 v2 的变更：整合 6 条评审修正（见 §13），并把「回归任务集」「文件结构」「里程碑」「第一周逐日任务」从草案落成可执行细节。
> 本文档定位：秋招第二顶级原创项目的实现蓝图 + 简历口径。先读 §0~§2 结论；§4~§8 给实现用；§9/§11 给写简历与面试前用。

## 0. 一句话定位

给一个自然语言工程目标，Agent 自主完成「规划 → 写码 → 跑测试 → 失败自修 → 全绿」的多轮长任务。全程沙箱隔离、可中断续跑、可审计回放、成本有护栏。原创实现，DeerFlow / DeepSeek 公开架构 / MyCoder 只作架构参照，不 fork、不抄码。

## 1. 为什么是「代码/工程任务」（对标问题，而非对标框架）

- 行业 Hot 项目（Claude Code / DeepSeek Harness / MyCoder）解决的同一类工程问题：长时域任务里的运行治理。
- 代码任务天然具备：真实副作用（装包/跑测试/写文件）→ 逼出工具治理；自然语言目标可驱动 30min~数小时 → checkpoint 变刚需；文件系统/进程 → 沙箱与漂移识别有主场；pytest 确定性验收 → 能报真数字。
- 原创差异化 = 自己的运行时内核长在代码任务上，不是再造通用底座，不是 fork 开源改个皮。

## 2. 核心决策（已定，含理由，防跑偏）

| 决策 | 结论 | 为什么 |
|---|---|---|
| 场景 | 代码/工程任务；旗舰 demo=「自修一个 Python 包到全绿」，架构保持场景无关 | 最贴 JD、叙事最真、长时域价值全被逼出 |
| 内核路线 | 自研 agent loop + 工具注册表 + 上下文预算 + 自研持久化（checkpoint/resume/漂移）；LangGraph 只做 DAG 低级构建，不碰状态（路线 A） | 纯自研风险高、纯 LangGraph「你造了啥」答不上；自研持久化守住「原创 Harness」叙事 |
| 范围 | MVP=韧性主线垂直贯穿（checkpoint+resume+漂移+恢复，从 L0 到工作台 UI「中断恢复」按钮）；技能注册表/记忆/多 Agent 委派/成本仪表盘只服务主线，其余后移 | 先深后广，质量靠「深」不靠「全」 |
| 沙箱（v2.1 修正） | 先轻量沙箱（临时目录隔离子进程 + 资源限制/超时）；Docker 放 L3 升级 | Docker 镜像构建/挂载/清理会啃掉一周；MVP 用轻量隔离已足够演示隔离+漂移 |
| 验收 | pytest 为主做确定性验收 | 测试过=过，可报「X/Y 通过」类硬数字 |
| 首个任务域 | 自修一个 Python 包（带 pytest 与文档）到全绿 | 单测做验收，自修闭环最清晰，代码量可控 |
| 前端栈（v2.1 补） | 复用海龟汤的 Next.js/React，不另起炉灶 | 省一周试错，模式已熟 |

**持久化落地方式（v2.1 修正 ①，防「自研」拖垮工期）**：
- checkpoint 状态先用 SQLite + JSON 序列化落盘（loop 当前步骤 / 已做动作 / 上下文摘要 / 工作区状态）。
- 漂移识别先做文件哈希快照前后比对（几十行代码），别等完美方案。
- LangGraph 持久化只留作兜底开关：若自研恢复正确性在 M2 末仍不稳，允许切它——叙事仍以自研为主，代码里留 `PERSISTENCE_BACKEND = "self" | "langgraph"` 配置位。

## 3. MVP 底线（五条，全要能产出硬证据）

> 教训：别在「好不好」不可判定的空间报 100%（写简历/调研），验收必须在确定性空间。

1. 单条长任务自修到绿：给一个会失败的目标，Agent 能 规划→写码→跑测试→读失败→自修→全绿。证据：`pytest` 退出码 0 + 测试数 N 全过。
2. 进程杀死可恢复：跑到一半杀进程，resume 后不重复劳动、续跑至绿。证据：录屏/日志对比 resume 后未重跑已完成步骤，最终全绿。
3. 工作区漂移可识别：任务中外部进程改了文件，resume 能识别「这不是我写的」、不误用脏状态。证据：漂移检测日志命中 + 恢复后任务仍全绿。
4. 预算护栏真实触发过：调低 token 上限，证明「超限 → 暂停 → 人工批准续跑」真走过一次。证据：审批记录（时间/批准人/续跑结果）。
5. 固定回归任务集全绿：自建 5~8 条难度分层代码任务全绿，记录 token 用量，报「X/Y 通过、Z 在预算内」。证据：`tasks/run_all.py` 输出表。

## 4. 模块拆解（分层；韧性主线垂直贯穿；落文件）

```
codecraft-harness/
├─ backend/
│  ├─ app/
│  │  ├─ main.py              # FastAPI：/api/tasks、/api/tasks/{id}、/api/tasks/{id}/resume
│  │  ├─ runtime/             # Layer0 核心（自研）
│  │  │  ├─ loop.py           # agent loop：规划→执行→看结果→再决策（自研）
│  │  │  ├─ plan.py           # 任务拆 DAG/步骤图（静态 JSON 计划；LangGraph 仅作低级构建）
│  │  │  ├─ context.py        # 上下文分层/预算裁剪 + 压缩率统计（量化点）
│  │  │  ├─ checkpoint.py     # 状态落盘/恢复（SQLite）——自研，见 §2 落地方式
│  │  │  └─ drift.py          # 工作区文件哈希快照比对（漂移识别）
│  │  ├─ tools/               # 工具注册表 + 治理
│  │  │  ├─ registry.py       # schema(Pydantic) 校验 / 权限分级 read|write|exec
│  │  │  ├─ approval.py       # 高危审批（装包/白名单外写文件）→ 人工批准续跑
│  │  │  └─ sandbox_exec.py   # 轻量沙箱：临时目录子进程 + 超时/资源限制
│  │  ├─ verifier/
│  │  │  └─ pytest_runner.py  # 跑 pytest，解析 stdout → 「红 N 条/文件:行」喂给 loop
│  │  ├─ store/               # SQLite：runs / checkpoints / traces / usage
│  │  └─ trace/
│  │     └─ recorder.py       # 每步：输入/工具调用/输出/成本，落盘可回放
│  ├─ tasks/                  # 回归任务集（工厂脚本 + 任务包），见 §6
│  │  ├─ run_all.py           # 全量回归：输出 X/Y 通过、token 用量表
│  │  └─ t1_single_fix/ … t6_cross_file/
│  ├─ tests/                  # 本项目自身 pytest
│  └─ data/                   # sqlite/轨迹（.gitignore）
├─ frontend/                  # Next.js 工作台：提交任务/进度/trace/中断恢复按钮
└─ docs/执行计划_v2.1.md
```

- Layer 0 核心运行时（主线必深）：agent loop；工具注册表+治理（参数校验/权限分级/高危审批/重复调用拦截/敏感脱敏）；上下文预算/压缩；自研持久化（checkpoint/resume/漂移）；run trace 落盘。
- Layer 1 场景层（代码任务）：轻量沙箱执行器；pytest 验收器；自修闭环（读失败→定位→改→重测）。
- Layer 2 Web 工作台：提交任务/看进度/看 trace/「中断恢复」按钮（韧性主线到 UI）；成本仪表盘（护栏是默认配置）。
- Layer 3 增量（非 MVP；服务主线才做）：Skills 注册表（SKILL.md 声明式，参考 anthropics/skills）；多 Agent 委派；长期记忆（mem0 式）；异步队列（Celery/Redis）；Docker 真沙箱。

## 5. 成本护栏（Day 1 默认，不是 L3 仪表盘）

对会跑几十分钟、烧真金白银 token 的任务，预算上限 + 超限暂停 + 仅人工批准续跑是默认配置。它同时提供：审批流的真实触发场景（MVP 底线 4），与一句能进简历的「处理过 token 成本失控」。默认预算由回归任务实测校准：每任务跑 2~3 次取 token 中位数 ×1.5。

## 6. 评测与回归（可信度来源；v2.1 已把任务集草案定稿）

> 参考 MyCoder 的教训：评测分层，别把「模型能力」与「系统能力」混为一谈。

- 回归任务集（6 条起步，弹性扩到 8）——第 1~2 周内定稿，不是后期：

| 编号 | 难度 | 任务类型 | 埋点 | 验收（确定性） | token 预估 |
|---|---|---|---|---|---|
| T1 | 入门 | 单测修复 | 1 个函数边界条件错，1 测试红 | pytest 全绿 | 5~10k |
| T2 | 简单 | 补缺失函数 | 模块引用了被清空的函数 | pytest 全绿 | 10~20k |
| T3 | 中等 | 修跨文件 suite 红 | 一处逻辑 bug 致 3 测试红，原因跨 2 文件 | pytest 全绿 | 15~30k |
| T4 | 中等 | 实现带测试的功能 | NotImplementedError + 已写好用例（读文档字符串实现） | pytest 全绿 | 20~40k |
| T5 | 较难 | 重构保绿 | 实现冗余/慢，要求不改测试、保持全绿 + 隐藏质量断言（耗时上限） | pytest 全绿 + 耗时断言过 | 30~60k |
| T6 | 较难 | 跨模块集成 bug | 函数签名改了调用方没同步 | pytest 全绿 | 20~40k |

  每个任务包 = 一个自带 pytest 与文档的小 Python 包，由 `tasks/factory.py` 生成（保证可复现、可重置——AI 改坏了能一键恢复）。
  T7/T8（弹性）：需要装第三方依赖（测沙箱装包 + 审批触发）；含糊需求长任务（测规划与上下文预算）。

- 韧性模块收益：进程杀掉 mid-run → resume 成功率 / 不重复劳动率。
- 上下文治理收益：开/关分层压缩 → prompt 长度对比（平均压缩率 %）。
- 恢复正确性：workspace 漂移识别率。
- 跨模型稳健性（v2.1 强化）：回归跑在 ≥2 个模型后端 / 不同 seed 下，证明通过率来自系统而非背题。

## 11. 面试预对（v2.1 强化第三答）

- 「这不就是复刻 Claude Code / OpenHands 吗？」
  「架构参照，但每个模块是我自己实现的：我的 agent loop 处理 XX（自己逻辑）、持久化我重写存进我自己这套（SQLite checkpoint）、沙箱我造的是 XX（轻量临时目录隔离）。我的可测量差异是 XX（如恢复成功率/压缩率）。」
- 「为什么不用 LangGraph / 现成框架？」
  「我想要的是一个 Harness 的可观测 + 可治理 + 可恢复的叙事，自研更可控；LangGraph 只当低级图构建，不碰状态，所以状态恢复的全链路是我自己的。」
- 「测试是你自己写的，不算作弊吗？」（v2.1 强化）
  「两点：① 回归任务集固定公开，我测的是系统行为（resume 恢复率、漂移识别率、预算触发、上下文压缩率），不是任务成功率——这些数字反映运行时而非模型；② 任务在 ≥2 个模型后端 / 不同 seed 下都稳定通过，说明通过率来自系统而非背题。」

## 12. 里程碑之外：质量底线提醒（评审备忘）

- 别在「好不好」不可判定空间报数字；代码任务的好处就是 pytest 替你裁决。
- 每个量化数字都要能指到「哪个脚本、哪个日志文件、怎么复现」。
- 每周五跑一次 tasks/run_all.py，把回归表贴进项目 README，防最后突击凑数。
