# 业界对标调研：CodeCraft Harness 站在哪、差多少、怎么讲

> 日期：2026-09-08 | 目的：给"秋招顶级项目标准"的自我测评一个**不掺水的外部参照系**
> 方法：逐个检索规格说明点名的业界样例（MindBridge / MyCoder / MiniCode）+ 代码 Agent 赛道
> 公认标杆（OpenHands / SWE-agent / LangGraph）的真实技术资料，与 CodeCraft Harness
> 逐能力项对照。所有 star / 评测分 / 版本号均标注来源与检索日期，不凭印象写数。
> 口径延续历次诚实审计：**方向满分 / 工程扎实 / 发布面偏窄**，本文件把"差在哪一层"钉死。

---

## 1. 一句话结论

CodeCraft Harness 与规格点名的样例**站在同一个能力层**（自研 agent loop + 工具 + 记忆 +
上下文治理 + 评测闭环的"代码 Agent Harness"），且在有真实数字的维度（回归/恢复/压缩、
真实库端到端、测试隔离）不输样例；但样例大多**多了半层**——MyCoder 有 GitHub issue→PR 闭环、
MiniCode 有完整 TUI+交互审批、OpenHands 有 Docker 沙箱+多 Agent+大规模评测。这半层是
"工程完备度"而非"架构正确性"差距，属于**可叙事、可半日补、不推翻重做**的差距。

## 4. 逐项解读：差距的真实层次

### 4.1 架构正确性：本项目不输，且有独有证据
- 回归 6/6、杀进程恢复 3/3、压缩不损正确性、T4 真实库从"13 失败→13 缺陷全修→收官 3 局成功"——
  这类"**用真实 run 反推 harness 缺陷并逐条修**"的证据链，在公开样例的 README 里看不到第二份。
- 独有强项是**确定性护栏**：dup 拦截/page-walk/空转雷达/ToolError 喂回。样例普遍把可靠性
  押在"好模型 + 好工具面"上，本项目证明"免费模型 + 护栏"也能 100%——这是可讲、难抄的差异点。

### 4.2 工程完备度：样例普遍多出的"半层"
| 半层 | 样例代表 | 差距性质 | 补法（已评估，非本轮范围） |
|---|---|---|---|
| GitHub 闭环（issue→PR） | MyCoder GitHub mode | **发布面词** | ✅ 2026-09-08 已补（dcbf58d）：`git_branch/git_commit/git_push/gh_create_pr` 四工具 + `drive_task --github --workspace <clone>`；真机跑出**真实 PR** [codecraft-delivery-demo#1](https://github.com/VVR823/codecraft-delivery-demo/pull/1)（+39/-1）；附带修出 Windows git unborn 竞态（三层防线，见 README W11） |
| Docker 化 | OpenHands | **发布面词** | ✅ 2026-09-09 已补（2ebb87f）：Dockerfile + docker-compose + 双模式 entrypoint（默认 FastAPI :8000 / `drive <task>` 跑真机任务）；镜像含 .git → 容器内 git restore 考卷还原语义完整；data/ 命名卷持久化 run 会话可 resume；密钥零进镜像；CI docker job 背书（build + /health 冒烟 + drive 入口链，见 README W12）。面试口径"轻量进程沙箱 vs OpenHands 容器沙箱"双轨 |
| UI（哪怕是 TUI） | MiniCode 全屏 TUI | 展示词 | ✅ 2026-09-09 已补（475de8e）：**/console Web 控制台**——未追 MiniCode 的 rich/textual 全屏 TUI，而是消费现成 API（M4 B5 预留的 progress 轮询点）做纯静态单页：任务包下拉 + 新建 run + run 历史侧栏 + 详情（状态/步数/token/最近 12 步动作时间线）+ budget_paused 人工 approve 续跑。取舍：Web 页面试演示比 TUI 直观（开浏览器看 agent 一步步修 bug），且零前端依赖符合自研调性；TUI 的交互审批流（回车批准）与 API 审批是同一数据层，语义等价 |
| 多 Agent / 异步队列 / GraphRAG | OpenHands/MindBridge | **平台类词**（规格原话口径） | **不补**——M5 已决策：硬塞会稀释"代码 Agent Harness"叙事，与参照画像 MyCoder 对齐（它也没有） |
| 多模态 | — | 平台类词 | 不补（同上） |

### 4.3 评测姿势：MindBridge 唯一值得抄的点
MindBridge 样例最漂亮的不是技术栈，而是**冻结评测集**：45 例路由 F1=1.000、20 例安全探针、
24 例记忆用例，全部 frozen 在仓库里、可复跑。这跟本项目 T1~T4 任务包 + 110 单测是同一哲学
（固定考卷 + 可复跑 + 数字说话）。差距只在**规模与命名**：它可以叫"F1/HitRate"，本项目叫
"6/6、3/3、12.3%"——数字形态不同但证据力等价。面试可主动讲"我的评测集就是 tasks/ 下的
真任务包 + 真实库回归，等价于 SWE-bench 的自托管迷你版"。

### 4.4 为什么"不引 LangGraph"反而能讲
规格要求词里有 LangGraph，本项目刻意不引。对照 §2 事实：LangGraph 卖的是"图状态机 +
checkpoint + HITL + 多 Agent 库"，其中 checkpoint/恢复/人工审批与本项目自研能力**功能重叠**。
面试口径（已有 Q 系列预演）："我用 LangGraph 能更快 demo，但它的状态管理是黑盒——面试官
问'怎么保证恢复不重放'我答不上来；自研后每一层都能指到代码"。这是**能力词 vs 自研浓度的
取舍**，不是能力缺失。

### 4.5 压缩率数字的诚实校准（规格截图 vs 实测）
- 规格截图 MyCoder 早期 README：7082→5664、16.19%、最高 33.28%。
- 本项目：T2 短任务 12.3%、24 步长任务 55.5%（离线真实消息形态）。
- 口径：两者**不是同一度量**（MyCoder 值疑似压缩后累计 vs 本项目按单步 prompt 中位数），
  直接比数字是耍流氓。本项目 55.5%（长任务）> 16.19%（样例短任务口径）说明机制量级不虚；
  简历上**不写"超越样例"**，写自己的测量口径即可（§9 已如此）。

## 6. 综合段位（按市场顶级秋招简历项目标准）

| 维度 | 顶级样例水平 | CodeCraft Harness | 差距层 |
|---|---|---|---|
| 架构设计深度 | 自研内核 + 独到方法论 | ✅ 同层（护栏方法论是差异点） | 无 |
| 真实验证 | SWE-bench 大规模 / 冻结评测集 | ✅ 真实库端到端 + 固定回归（迷你 SWE-bench） | 规模小一个量级，证据形态等价 |
| 工程完备度 | 有 GitHub 闭环/Docker/UI 之一 | ✅ 三者皆有（W11/W12/W13） | **发布面差距已关闭**（深度另计：UI 是演示控制台级、Docker 是部署级，非产品级打磨） |
| 评测纪律 | 数字可复跑 | ✅ 110 单测 + 6 个报告，全部可复跑 | 无 |
| 开源发布 | 数百~数万 star | ⭐ 0 star（公开仓刚建 1 天） | 时间差，非能力差 |

**结论**：在"秋招个人原创项目"标尺上处于**顶级门槛内**——架构层不输样例、证据链更硬；
但**在"顶级完整度"标尺上曾差的发布面三缺已全部补齐**（GitHub 闭环 W11 / Docker W12 /
Web 控制台 W13——三者都是"已想清楚、可快速补、不动内核"的活，且直接喂给简历关键词：
GitHub Actions + 容器化 + 前端控制台均已落地）。**不值得为追平台类词（GraphRAG/多 Agent/
异步队列/多模态）开第三项目**——那些词硬塞会稀释现在的自研浓度叙事。
