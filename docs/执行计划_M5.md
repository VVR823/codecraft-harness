# CodeCraft Harness — M5 执行计划（JD 关键词补强：Skills + MCP + 长期记忆）

> 2026-09-06 定稿。背景：用户拿"项目推荐需求规格"逐条审计 M4 收官态，结论——作为第二原创项目
> 完全达标（参照 MyCoder 画像 1:1），但规格 §六 的 Harness 系新词有三个洞没堵：**Skills / MCP /
> 长短期记忆持久化**（均为 2025-11 后 JD 高频词）。用户拍板"都补，精益求精"→ 立 M5。
> 前置事实：M0~M4 全部收官（commit 78ddfcd / e34d0e3），单测 52/52，三硬数字 + 数字④ 齐。
>
> **红线（与 v2.2 Q 系列一致）**：三模块全部**默认关**，数字① 回归口径（no-plan / 无压缩 /
> 无技能 / 无记忆）一字不动；单测全绿是 B 块验收线；不引 LangChain/LangGraph（延续 Q5）；
> MCP 不引官方 SDK——协议最小子集自研（延续"自研浓度"叙事，面试可讲协议本身）。

## 1. 为什么是这三个（审计缺口 → 决策）

M4 收官后按规格 §六 关键词并集审计，❌/⚠️ 项里属于"代码 Agent Harness 该有"的洞：

| 缺口 | JD/规格依据 | 本项目现状 |
|---|---|---|
| **Skills / Skill 注册** | Anthropic Skills 165k★、2026 风口、JD"掌握 Skills" | 无技能体系 |
| **MCP** | 规格核心词、JD"掌握 MCP" | 无 MCP |
| **长短期记忆持久化** | JD 五大核心模块 ②"长短期记忆持久化" ⑤"记忆&成本管理" | 只有短期（会话内 checkpoint），无跨 run 长期记忆 |

不做：GraphRAG/多 Agent/Celery 队列/多模态（平台类项目词，硬塞稀释"代码 Agent Harness"叙事，
与参照画像 MyCoder 对齐——它也没有）。

## 2. 决策表

| # | 决策 | 结论 | 为什么 |
|---|---|---|---|
| P1 | Skills 形态 | 自研 SKILL.md 协议：目录含 SKILL.md（YAML frontmatter：name/description + 正文），`skills/` 仓库扫描发现，按 description 语义匹配 | 对标 Anthropic Skills 目录协议；不引框架，自己实现解析，延续 Q5 |
| P2 | Skills 注入 | 匹配的 skill 注入 system prompt 尾部（指令性内容）；`--skill-dir` 可指定，默认关 | 不污染默认执行；面试演示"技能改变行为"可 A/B |
| P3 | MCP 客户端 | **不引官方 SDK**：自研最小 stdio client——`initialize` → `tools/list` → `tools/call`（JSON-RPC over stdio） | 零新依赖；面试能讲 MCP 协议本身（四层：protocol/transport/server/client） |
| P4 | MCP server | 自带一个 demo server（stdio）：暴露 1~2 个只读工具（如 sqlite 查询） | 演示闭环：agent 经注册表调 MCP 工具，trace 全程可审计 |
| P5 | MCP 工具命名 | 动态注册进工具注册表，`mcp_<server>__<tool>`；decision 校验放行前缀 `mcp_` | 注册表仍是唯一入口（describe/执行/审计同源），决策协议不改 JSON 结构 |
| P6 | 长期记忆 | 新表 `memories`：跨 run 记忆条目（run_id/task_id/kind/content/ts）。写入点：run 结束沉淀（成功路径/失败原因）；读取点：run 开始时按 task_id 检索注入 | 短期=checkpoint（本轮），长期=跨 run 经验（复用/防重踩坑） |
| P7 | 记忆开关 | `--memory` 默认关；开时注入"历史记忆"段落 + 结束沉淀 | 与 plan/compress 同构：默认关保口径，长/重复任务按需开 |
| P8 | 范围收敛 | 三模块最小闭环 + 单测 + 文档，不做花哨演示 UI | M5 时间盒 ~2-3 天，够用线优先 |

## 5. 诚实口径（面试用）

- Skills/MCP/记忆都是**默认关的增量**：它们不改变 6/6 基线的"纯净口径"——面试官若问
  "加了这些是不是才到 6/6"，答：6/6 是裸 harness + 四护栏跑出来的，三个模块是面向
  JD 关键词的**能力扩展**，各自有独立单测与演示，不掺进基线数字。
- MCP 用自研最小客户端而非官方 SDK：面试若问"为何不用 SDK"，答：为了把协议层讲透
  （JSON-RPC over stdio、initialize 握手、工具发现），生产环境换官方 SDK 是半小时的事，
  协议理解不依赖 SDK。
- 长期记忆是"经验复用"不是"知识库"：沉淀的是本任务成功/失败路径（行为记忆），不做 RAG。
